# windows-headless — Implementation Plan

## 1. Goal
New Rust library crate `windows-headless` + thin example CLI that implements the full zero-touch headless Windows 11 Enterprise Eval pipeline discussed: download ISOs → generate hardened `autounattend.xml` → expose via vvfat folder → create sparse qcow2 → launch `qemu-system-x86_64` headless → poll SSH until ready. No GUI prompts may block; all hangs must be diagnosable headlessly.

Confirmed scope (user):
- **Crate scope:** library with `HeadlessVmBuilder` API + `examples/` / thin CLI for CI.
- **QEMU backends:** KVM (Linux) + HVF (macOS) + TCG software fallback.
- **Answer-file transport:** install tree on a USB-HDD FAT32 image (built from the ISO's UDF tree + wimlib-split install.swm + VirtIO drivers + answer XML at root); answer file ALSO staged in a vvfat dir (both scanned). Verified live: 25H2 ISO is UDF-only and this EDK2 has no UDF driver (UDF discs map BLK-only); ISO9660 rebuilds die on 8.3 truncation (`microsoft` → `MICROSOF`, BCD unfindable); USB boot needs no keypress and Setup runs fully. Never attach installer media `readonly=on` (Windows skips volumes on readonly USB).
- **SSH auth v1:** password only (`AdminUser` / configurable password, guest :22 → host :2222). No key-injection/ACL hardening in v1.

## 3. Module Specs

### 3.1 `unattend.rs` — dynamic template generator (no hardcoded XML)
- `pub enum Architecture { Amd64, Arm64 }` + `as_xml_str() -> "amd64"/"arm64"`; `pub struct VmConfig { username, password, locale (default en-US), timezone, arch, virtio_iso_drive: char (default E), auto_logon: bool (default false) }` with Builder (`HeadlessVmBuilder` forwards `.username()/.password()/.locale()/.timezone()/.arch()/.virtio_drive()/.autologon()`).
- `VmConfig::generate_unattend_xml() -> String` via `format!` (or `tinytemplate` — decision at implementation; must XML-escape `username/password/locale` via `quick-xml::escape`). All `processorArchitecture="{arch}"`, all locale tags from `locale`, `DriverPaths` as `{drive}:\vioscsi\w11\{arch}` + `{drive}:\NetKVM\w11\{arch}` (drive letter follows QEMU attach order; default E, configurable F).
- Fixed hardened passes (from brief) rendered around injected vars — full set required (starter draft was missing items, fixed here):
  - `windowsPE`: International-Core-WinPE locales; Setup `DriverPaths`; RunSynchronous **all five** BypassTPM/BypassSecureBoot/BypassRAM/**BypassCPU/BypassStorage** (Order 1–5, `HKLM\SYSTEM\Setup\LabConfig`); DiskConfiguration Disk 0 EFI 300MB/MSR 16MB/Primary Extend + ModifyPartitions with Labels (`System` FAT32, `Windows` NTFS `C`); ImageInstall Disk 0 Part 3 `WillShowUI OnError`; AcceptEula.
  - `specialize`: OpenSSH install + `Set-Service sshd Automatic` + `Start-Service` + firewall via **`New-NetFirewallRule ... -LocalPort 22`** (not `netsh`, standardized) + BypassNRO + **`DisablePrivacyExperience=1`** (was missing from draft).
  - `oobeSystem`: LocalAccount + full OOBE set (**HideEULA/HideLocal/HideOEM/HideOnline/HideWireless + `NetworkLocation Work` + `ProtectYourPC 3`**) + `<TimeZone>{tz}</TimeZone>` + `AutoLogon` only if `auto_logon=true`.
- `auto_detect_platform() -> (Architecture, accel)`: `std::env::consts::ARCH` (`x86_64`→Amd64, `aarch64`→Arm64) + OS (`linux`→kvm, `macos`→hvf, else tcg fallback; WHPX explicitly not v1). Builder defaults `arch/accel` from host, overridable; `qemu-system-x86_64` vs `qemu-system-aarch64` binary follows `arch`.
- Tests: render amd64+arm64 snapshots; assert `InstallTo`, `DriverPaths` with right drive/arch, Bypass keys, DisablePrivacyExperience, AutoLogon absent by default / present with flag; assert escaping (`P@ss<>&"` round-trips); `quick-xml` well-formedness check.

### 3.2 `downloader.rs`
- Targets: Win11 Enterprise Eval URL (explicit `--win-iso-url` / `$WIN11_EVAL_ISO_URL` only — no page scraper; EvalCenter links require the interactive form) + stable VirtIO `https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/stable-virtio/virtio-win.iso` (NOT `latest-virtio` for CI stability). Canary CI fetches via Fido (drives the real download API).
- Streaming `reqwest` → file, on-the-fly `sha2::Sha256`, `hex`-encoded digest; `.part`-sibling download + rename so interrupted runs never poison the cache. `download_if_missing(url, dest, expected_sha256)` skips present files (hash-verified when expected given). Expose `download(url, dest)`, `download_if_missing`, `sha256_of`, `fetch_eval_iso_url`.
- Cache location via `cache-manager` 0.4 (default features, zero transitive deps): `$WINDOWS_HEADLESS_ISO_DIR` override else `<project>/.cache` discovery; `ensure_group("iso")` with **no `EvictPolicy`** — max cache size off (no `max_bytes`/`max_files`/`max_age`), documented in code; `./.cache/` gitignored. CLI `fetch` subcommand resolves this dir.
- Integrity: `validate_iso_image()` (ISO9660 `CD001` magic) runs in `fetch` (bogus cached files are deleted and re-downloaded) and as a `run` preflight — a bot-wall HTML page saved as `.iso` (HTTP 200) otherwise hangs EDK2 at boot with zero block I/O and a black screen.
- Firmware strictly portable: `firmware_code()` resolves only inside `<qemu-dir>/share/qemu`; no host paths probed. `require_firmware()` errors without `--qemu-dir` or with a firmware-less tree.
- No Eval-page scraper in v1 (dead approach — links are form-issued); Fido for canary CI, Mido.sh documented as shell alternative in README.

### 3.3 `storage.rs` — qcow2 + vvfat staging (no ISO tools by default)
- `ensure_unattend_dir(path, xml)`: `mkdir -p`, write `autounattend.xml` at dir root, verify `ls`. No `genisoimage`/`xorriso`/`mkisofs` dependency in default path.
- QEMU attaches it as `-drive file=fat:ro:<dir>,format=raw,if=ide` (NOT `if=virtio` — WinPE reads the answer file before `DriverPaths`/vioscsi loads, so the bus must be inbox IDE/AHCI/USB). QEMU presents it as raw FAT disk (USB-like, drive D:/E:); Setup scans every volume root and picks up `autounattend.xml`.
- Freeze rule: FAT table is snapshot at QEMU launch — never modify `<dir>` while VM runs (corrupts guest view). Builder writes XML → then spawns QEMU; CLI must enforce this ordering.
- Caveats: vvfat `ro` only (avoid `rw` corruption); keep dir to single `autounattend.xml`.
- Opt-in fallback (enterprise CI, Packer-style): `--unattend-iso` builds 1MB `unattend.iso` via `mkisofs -o unattend.iso -J -r <dir>/autounattend.xml` and attaches as `-drive file=unattend.iso,media=cdrom,readonly=on` (inbox ATAPI, VirtIO-independent). `iso.rs` helper only compiled/used for this flag.
- Unit test: stage tempdir, assert `autounattend.xml` at root and valid XML; assert QEMU arg builder emits `if=ide` for vvfat and never `if=virtio`.

### 3.4 `storage.rs` (qcow2 + overlays)
- Base: `qemu-img create -f qcow2 <path> <size>G` (default 64G sparse); `resize` helper. Check `qemu-img` on PATH, surface stderr. No NBD in v1.
- `DiskManager::create_overlay(base, overlay)`: `qemu-img create -f qcow2 -F qcow2 -b <base> <overlay>` via `tokio::process::Command` + context/bail on failure. All overlay writes stay in overlay; reset = delete overlay + recreate. Unit test with tiny qcow2 fixtures (requires `qemu-img` else ignored).
- Clean-shutdown rule (load-bearing): never create overlay off a dirty NTFS base — `kill -9` leaves dirty bit → blocking `chkdsk` on next boot. Required order: `wait_for_ssh` → `shutdown_cleanly()` (`Stop-Computer -Force` over SSH, or ACPI `system_powerdown` via monitor) → wait for QEMU exit → then `create_overlay`. Builder enforces: `build_base(path)` installs once; `from_existing(overlay)` boots ephemeral (no install media/vvfat attached).

### 3.5 `qemu.rs` — orchestrator (+ `qmp.rs` for live snapshots)
- Accel select: Linux → `-accel kvm` (probe `/dev/kvm` writable, else TCG + warn); macOS → `-accel hvf`; fallback `-accel tcg`. Flags: `-m 4096 -smp 4` configurable.
- Drives: `file=<disk>,format=qcow2,if=virtio` (OS disk VirtIO OK — drivers load via DriverPaths after answer file) + `file=<win.iso>,media=cdrom,readonly=on` + `file=<virtio.iso>,media=cdrom,readonly=on` + answer drive: x86_64 `file=fat:ro:<unattend_dir>,format=raw,if=ide`; ARM64/`virt` (no IDE bus) USB mass storage (`qemu-xhci` + `usb-storage`, `if=none`) — both inbox buses, never `if=virtio`.
- Opt-in: `--unattend-iso` replaces vvfat arg with `file=unattend.iso,media=cdrom,readonly=on`.
- Net: `-netdev user,id=n1,hostfwd=tcp::<host_port>-:22 -device virtio-net-pci,netdev=n1` (default host 2222).
- QEMU source: portable `jzombie/lab-qemu-portable` releases into `<cache>/qemu-portable/<version>/` (SHA256SUMS-verified, quarantine-stripped on macOS), or system QEMU via PATH. `HeadlessVmBuilder::qemu_dir()` selects it; `system_bin()`/`img_bin()` resolve; `DiskManager` takes the img path.
- `virt` ships with no input devices: `-device qemu-xhci + usb-kbd + usb-tablet` (all inbox; tablet required for VNC pointer, kbd for send-key). x86/pc has PS/2 by default. Display on ARM is `ramfb` (single console: VNC/screendump keep working under Windows, matches UTM; virtio-gpu leaves screendump dark once Windows drives it). x86/pc has VGA. Both paths get `-serial file:<vm-dir>/serial.log` for dark-screen forensics.
- Display: `--display none|cocoa|gtk|vnc=<spec>` (default `none`); `run --vm-dir` anchors disk+unattend under project cache `vms/win11` (no eviction).
- Boot correctness: `-cpu host` on kvm/hvf; firmware via pflash pair (CODE readonly + per-VM VARS copy, portable tree only — NVRAM must persist the Windows Boot Manager entry across Setup reboots; verified: post-apply reboot loads Boot0005 from disk). x86 keeps `-boot order=d`, ARM64 omits it (EDK2 default boots the CD; explicit order drops to the UEFI shell). CD-flow "press any key" via QMP `send-key` (`{"type":"qcode","data":"ret"}`); USB flow needs no taps. ARM64 fails fast without `--qemu-dir` firmware.
- Diagnostics: always add `-monitor unix:<sock>,server,nowait`; `screendump(path)` helper sends `screendump <file>.ppm` via `nc -U <sock>` (document `magick display/convert` to PNG). Spawn via `tokio::process::Command`, optional `-daemonize` equivalent (detach + PID file) for CI; kill helper.
- QMP (`qmp.rs`, hand-rolled `serde_json` + `tokio::net::UnixStream`, no `qapi` crate): always add `-qmp unix:<qmp_sock>,server,nowait` alongside monitor. `QmpClient { writer: OwnedWriteHalf, reader: BufReader<OwnedReadHalf>, events: mpsc::UnboundedSender<Value> }`; `connect(path)`: read `{"QMP":...}` greeting → send `{"execute":"qmp_capabilities"}` → enter command mode. `execute(payload)`: attach unique `"id"`, newline-delimited write, `read_line` loop demuxing responses (match `id`) vs async events (`{"event":...}` like `DEVICE_DELETED` → forward to `events` channel, keep waiting). Methods: `live_overlay(node, overlay)` → `blockdev-snapshot-sync` with `node-name/snapshot-file/snapshot-node-name/format=qcow2` (modern node form; fall back to `device` on old QEMU), parse response for `"error"` key and bail; `screendump(path)`; `savevm/loadvm` via HMP escape hatch `human-monitor-command` (`savevm <name>`); `migrate_to_file(path)`. Document consistency tiers: live pivot without guest agent = crash-consistent (power-cut equivalent, NTFS journals replay — fine for throwaway CI); with Guest Agent + `guest-fsfreeze-freeze/thaw` (VSS) around pivot = fs-consistent. Guest-agent install (from `virtio-win.iso` `qemu-ga` MSI) opt-in, not default. Unit tests: handshake sequence, `id` demux with interleaved event, error-key detection — no live VM needed.
- `HeadlessVmBuilder::new(WindowsVersion::Win11EnterpriseEval).disk_size_gb().memory_mb().smp_cores().enable_ssh().ssh_port().vnc().monitor_socket().qmp_socket().build()` → downloads, renders XML, stages vvfat dir, creates img, spawns QEMU. Extended API: `.build_base(path)` (install phase with ISOs+vvfat) / `.from_existing(overlay).start()` (ephemeral boot, install media detached) / `.snapshot_live(overlay)` / `.savevm(name)` / `.shutdown_cleanly()` / `.kill()`; CLI gains `build-base`, `overlay <base> <out>`, `boot <overlay>`, `snapshot-live`, `savevm/loadvm`, `shutdown` subcommands. Golden-master flow (shutdown → `create_overlay`) stays the default safe path; live QMP pivot is the zero-downtime option with documented crash- vs fs-consistent tradeoff.

### 3.6 `ssh.rs`
- `wait_for_ssh(host, port, timeout)` — TCP connect **plus `SSH-2.0-*` banner read** (bare connect is a false positive: QEMU slirp completes the host-side handshake while the guest is still in UEFI/Setup, so connect-only polling declares "ready" in seconds and the real `ssh` then hangs). Banner wait capped at 10s / remaining budget; 15s poll interval capped at remaining budget. Success → return; timeout → attempt `screendump /tmp/failure_state.ppm` via QMP, then hard error. Document `ssh -o StrictHostKeyChecking=no -p 2222 AdminUser@127.0.0.1 "cmd.exe /c ver"`. Tests: banner success, closed-port fast fail, silent-accept regression (accept-without-banner must not resolve).

### 3.8 CI `.github/workflows/test-windows-pipeline.yml` + `canary.yml`
- PR CI (`test-windows-pipeline.yml`): `runs-on: ubuntu-latest`: udev KVM rule + `udevadm trigger`, `apt install qemu-system-x86 qemu-utils netcat-openbsd` (no genisoimage needed in default vvfat path), `actions/cache@v4` on `iso/*.iso` + `base.qcow2` (install once, reuse), stage `./unattend_dir/autounattend.xml`, sparse `qemu-img create`, background QEMU launch with `file=fat:ro:./unattend_dir,format=raw,if=ide`, SSH poll loop, `ssh ver` assert, `Stop-Computer -Force` clean shutdown before caching/uploading base. Ephemeral jobs use `qemu-img create -b base.qcow2` overlays for seconds-fast boot. Note 14GB disk caveat + Android-SDK cleanup snippet.
- Weekly canary (`canary.yml`, `cron: 0 2 * * 0` + `workflow_dispatch`): no base cache — always fetches latest Eval ISO (curl EvalCenter page → grep `software-static.download.prss.microsoft.com` `amd64_English` `.iso`, fallback Fido script) + stable virtio-win.iso, then `cargo test --test canary` with `LATEST_WIN11_ISO`/`VIRTIO_ISO` envs. Fail-fast 25 min timeout (nested-KVM headroom over the 15 min PR budget); on timeout `screendump /tmp/ci_failure.ppm` via QMP/monitor and `panic!`; `actions/upload-artifact@v4` uploads the PPM on `failure()` so a new MS screen (e.g. Copilot sign-in on 25H2) is visually diagnosable. New `tests/canary_test.rs` (`#[tokio::test] test_latest_windows_headless_pipeline`): `build_and_start` → `timeout(25min, wait_for_ssh)` → `ssh_exec("...Win32_OperatingSystem...")` asserts `Windows 11` → `shutdown_cleanly`. Gated `#[ignore]` locally unless `LATEST_WIN11_ISO` set.

## 4. Dependencies (proposed `Cargo.toml`)
`tokio(process,net,time,macros,rt-multi-thread,io-util,io-std)` (io-util/io-std required for `AsyncBufReadExt`/`AsyncWriteExt` + split UnixStream in `qmp.rs`), `reqwest(rustls-tls,stream)`, `sha2`, `anyhow`, `clap(derive)`, `serde(-)`, `serde_json` (QMP), `quick-xml` (test/validate + escaping), `tempfile`, `tracing/log`, `indicatif` (optional). QMP via std `tokio::net::UnixStream` JSON (no `qapi` crate in v1; monitor still via `nc -U`). No ISO authoring deps in default path — vvfat only (`mkisofs` only for opt-in `--unattend-iso`).

## 5. Verification
1. `cargo fmt && cargo clippy -- -D warnings && cargo test` (XML content tests, vvfat staging test, SSH timeout-fast-fail test with 1s timeout, QMP JSON builder tests without live VM).
2. Linux KVM manual run: `cargo run --bin windows-headless -- run` → SSH poll succeeds → `ssh -p 2222 AdminUser@127.0.0.1 "cmd.exe /c ver"`; on failure assert `/tmp/failure_state.ppm` written and non-empty.
3. `screendump` smoke: launch with `-monitor`, trigger `screendump`, `file` shows PPM.
4. GHA workflow dispatched on branch; cache hit/miss both paths exercised.
5. `cargo doc` clean; README documents Fedora stable-virtio rationale, Eval-Center scraping, VNC-vs-none, PPM viewing.
6. `docs/oobe-bypass-runbook.md` documents the canary-red → bypass-green loop: (a) repro locally with `-display gtk/cocoa` + Shift+F10 SYSTEM cmd, export `HKLM\...\OOBE` before/after clicking through, diff for new DWORD (add to specialize `RunSynchronous`); (b) inspect `C:\Windows\SystemApps\Microsoft.Windows.CloudExperienceHost*` JS/JSON for the skip flag/policy; (c) check ADK Unattend schema for new `<OOBE>` child; (d) track Rufus `rufus.c` / Packer templates / `dockur/windows` (usually patched ≤48h after Insider build). Each new bypass lands as a `RunSynchronous` reg entry + canary re-run.

## 6. Explicitly Out of Scope (v1)
Key-based `administrators_authorized_keys`+`icacls`, custom guest `sshd_config Port`, WHPX/HAXM, recovery-partition layout, multi-language UI beyond en-US, Win10/Pro consumer SKUs (enum stub only). Guest-agent auto-install + fsfreeze orchestration stays opt-in (documented, not default).
