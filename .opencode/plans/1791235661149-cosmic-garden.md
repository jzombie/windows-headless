# Activity-aware install status (classifier x I/O, no false alarms)

## Problem
The CNN misclassifies ~22 base captures (progress↔progress, consoles→ErrorShell,
white setup windows→ErrorScreen/OobeStep). Instant WARNINGs on error reads would
false-alarm on transient misreads, but pure persistence debouncing is wrong: slow
installs legitimately hold one screen for hours. Resolution: gate warnings on
guest activity (disk I/O + disk growth), not wall-clock alone.

## Severity of current misses (why this is safe to ship)
- Progress↔progress (InstallerStep↔OobeStep, ~14 files): zero operational effect.
  Both mean "keep waiting"; only the log noun changes.
- False-error reads (consoles→ErrorShell, license-terms→ErrorScreen): those
  screens are unreachable in automated flows (unattend auto-accepts EULA, no
  manual consoles). They appear only in human-driven runs.
- Activity gating makes even manual-run misreads non-alarming unless the guest
  is actually parked (no I/O + no growth). No fixture moves, no retrain.

## Changes

### 0. `SamplingProfile` (new struct, `src/timeouts.rs` or `src/commands.rs`)
- One place resolving cadence policy from the accelerator (`accel() == "tcg"`,
  same predicate `cpu_model()` uses — no new detection): TCG → classify
  every 30s, hardware accel → every 10s. Disk-save cadence unchanged (60s
  default) on both.
- Explicit `--classify-every-secs` always wins over the profile; the profile
  only supplies the default. No scattered `if tcg` at call sites: `run`,
  `install`, and the chain constructor take a `SamplingProfile` and read both
  intervals off it.
- Rationale: full-tick cost (screendump + PNG-best + CNN) is hundreds of ms
  of one host core — fine on hardware accel, worth spacing 3x on pegged
  TCG boxes. Disk-save ticks dominate via PNG compression, so they stay put.
- Single tick authority: `SamplingProfile` owns the tick schedule. Both the
  install task (`spawn_screenshots`) and the run boot-loop tick off the
  profile's interval — no independent `interval()` computations, no parallel
  tickers. Due-checks (`save_due`, classify-due) read profile intervals, so
  there is exactly one place deciding when anything captures.
- Ownership (profile drives nothing, it only answers "how often").
  One role per struct, one verb each — the current time-lapse task
  orchestrates, captures, announces, and would now feed two more holders,
  which is the smell. It dissolves below. Split:
  - `SamplingProfile`: pure policy, no state, no I/O. Three intervals in,
    accel-aware defaults, explicit flags win. Answers "how often".
  - `ScreenSampler`: owns the ticker, the screendump, the frame buffer,
    classification, and motion diff. Answers "what does the guest look
    like now". No announce, no policy.
  - `ActivityMonitor`: I/O counters, disk-size samples, EMAs, idle math.
    Knows nothing about screens. Answers "is the guest doing anything".
  - Reporter (thin announce + warning policy in the loop body, not a new
    type unless it grows): reads sampler + monitor, writes lines, fires
    WARNINGs on the conjunction. Answers "what do we say".
  - The warning conjunction is the only place screen state and activity
    meet, keeping sampler and monitor independently unit-testable.
- Migration (explicit, so the old shape does not linger): `InstallerWatcher`
  is removed as a symbol entirely — deleted, not renamed (renaming lets the
  old responsibilities hide under a new noun). Its ticker, screendump calls,
  frame buffer, and counters move into `ScreenSampler`; its announce/`WARNING`
  blocks move into the reporter path; `ActivityMonitor` is new code with no
  predecessor. The run boot-loop's inline ticker body gets the same
  treatment: capture/classify via the sampler, lines via the reporter.
  After the change, `grep InstallerWatcher` must come back empty.
- Unified ticker: serial narration becomes a third due-check on the same
  tick, not its own interval. Tick interval = min over all active cadences
  (narration, save, classify), same pattern as the earlier cadence fix. One
  ticker per loop, three due-checks, zero alternate capture paths.
- `BOOT_STATUS_TICK` does not survive as a separate constant: the profile
  owns all three cadences, narration included. It becomes a `DEFAULT_*`
  narration default consumed by the profile like the other two (rename per
  the constants convention, e.g. `DEFAULT_BOOT_NARRATION_SECS`). No orphan
  constants outside the profile.

### 1. `ActivityMonitor` (new struct, `src/commands.rs` near `BlockIdle`)
- Samples per tick: `info blockstats` totals (reuse `BlockIdle::parse_total`),
  plus `metadata().len()` on `<vm-dir>/disk.qcow2` (host-side, no monitor
  round-trip).
- Exposes: `idle_secs()` (since last I/O movement), `growth_since_start()`,
  `is_moving()` (idle < IDLE_WARN_SECS).
- Pure sample/derive split: `sample()` is async (monitor call + fs stat),
  all math on stored counters → unit-testable without QEMU.
- Sampling rates (pinned): both signals sampled every 10s tick alongside
  classification. blockstats is bytes back on a socket already moving
  megabytes per screendump — negligible. Disk stat is microseconds but
  judged ONLY as deltas over 30–60s windows: qcow2 grows stepwise (64KB
  clusters, lazy flushes), so per-second diffs false-report static.
  Judgment horizons stay at the existing IDLE_WARN (60s) / IDLE_BAIL (120s);
  new signals plug into those thresholds, no new timing constants.

### 2. Terminal stats lines (install + run loops)
- Install (sampler task) and run boot-loop status lines gain an
  activity suffix: `(Windows Setup progress, disk +12MB, I/O moving)` /
  `(ERROR needs input, no I/O for 95s, disk static)`.
- Proof-of-life for 3-hour installs: movement shown, never judged.
- Compact per-tick stats, scrollback-safe: one short line per classify tick,
  carrying since-last-read deltas (I/O bytes, disk growth), since-last-phase-
  transition totals (time in current screen state, I/O + growth accrued
  since the state changed), and exponential moving averages (I/O bytes/s,
  growth/s over ~5min windows) so bursts read as rates, not spikes.
  No multi-line dumps, no per-second chatter: the tick line is the whole
  instrument panel, e.g.
  `installer status 12: (Setup progress, phase 4m12s, io 1.2MB/s avg, disk +38MB this phase)`.
- Pixel-motion signal ("transition" means pixels moved, not label changed):
  thresholded mean-abs-diff at grid resolution against the previous tick's
  frame — never naive any-pixel-changed, which VNC noise and cursor blink
  keep permanently true. Per-tick record is (frame buffer, screen state,
  instant): the buffer feeds motion, the state feeds phase tracking, the
  instant feeds every duration. One record, three signals, no separate
  bookkeeping per consumer. One extra frame buffer in memory (trivial next to
  the CNN); threshold set empirically above blink-plus-compression magnitude
  (verify against a real parked capture: blinking cursor must read static).
  Surfaces as `screen static Ns`. Static + moving I/O = slow install, alive.
  Static + flat I/O = parked. Cheapest stuck signal in the design, needs no
  classifier, never judges alone (still screens with live I/O stay alive via
  the conjunction).

### 3. Warning policy (classifier x activity)
- Error state + moving → log state, no WARNING (transient misread or live recovery).
- Error state + flat beyond IDLE_WARN_SECS → WARNING with evidence
  (screen + idle duration + static size). Beyond IDLE_BAIL_SECS → existing bail.
- Keeps current warn-once/bail semantics of `BlockIdle`; activity only adds the
  classifier conjunction and the disk-growth signal.

### 4. Margin-hedged wording (follows the same conjunction)
- Plumb margin out: `predict_full` → `classify_screen` return
  `(ScreenState, f32)`, through `take_screenshot`/`classify_only` into announce.
- Error read below margin threshold const (1.0): `may need input (uncertain)`
  instead of `needs input`; WARNING still requires the activity conjunction.
- `format_failure_report` gains activity evidence (idle secs, growth bytes).

## Trainer follow-ups (same session direction, separate work)

### Manual checkpoint (operator step, before anything moves)
- Operator manually copies the current trainer source aside and commits it
  (plus the current `artifacts/weights.bin`) as the pinned baseline. No
  agent, no automation: the point is a human-owned record that later diffs
  compare against.
- After the `src/bin` move, `diff` the moved file against the committed
  blob — the move must be byte-identical apart from the path. Same for any
  future weights retrain: the committed bytes are the diff base, so silent
  divergence is impossible by construction.
- Nothing below starts until that commit exists.

### Resume training (warm start, no scratch restarts)
- `train-screen-cnn` loads `artifacts/weights.bin` as init when present and
  shape-matching (existing fail-hard size assert guards architecture drift);
  falls back to He init otherwise. `--from-scratch` forces fresh init.
- Every resume opens with a pre-evaluation run: full BASE verdict + HOLDOUT
  report on the loaded weights BEFORE epoch 0, printed in the same format
  as the training lines. That is the established baseline the fine-tune is
  judged against — no baseline, no claim of improvement.
- Same seeds + same corpus + warm start stays reproducible; new captures
  fine-tune in a short run instead of a full retrain. LR unchanged (short
  run, same landscape); revisit only if fine-tunes oscillate.
- Acceptance: stop a run early, add a capture, resume — converges in a
  fraction of full-train epochs with identical log format.

### Trainer moves `examples/` → `src/bin/`
- `examples/train_screen_cnn.rs` becomes `src/bin/train-screen-cnn.rs`
  (real CLI surface: `--from-scratch`, future `--epochs`, `--patience`).
- No logic change in the move; update doc references (README recipe lines,
  `screen_cnn.rs` module docs naming the example path, FAIL_HARD message
  text pointing at the example command).
- Acceptance: `cargo run --bin train-screen-cnn` trains; clippy clean with
  bins included (already covered by `--all-targets`).
